# Agent Note: Repository collaboration rules

Status: implemented

## Problem

仓库协作需要明确修改授权、事实归属与验证责任，避免依赖单次对话中的约定。

## Decision

以根目录 AGENTS.md 作为协作入口，具体任务按需加载 `.agents/skills/` 中的指导；决策记录的路径和格式由 `.agents/notes/README.md` 统一定义。检查选择依据实际改动及仓库已有命令，规则的语义适用性由评审判断。

README 面向使用者，保留产品能力、安装使用、统计限制与隐私说明；开发命令和运行机制由 AGENTS.md 承接，像素布局与渲染细节继续归界面设计文档。这样既缩短产品入口，也让开发者能找到完整技术约束。产品截图复用真实视图的离屏渲染与示例数据，避免暴露实际网络地址；选定图片随仓库保存，生成方法归 AGENTS.md，便于界面变化后同步更新。

## Alternatives considered

- 仅保留对话约定：后续协作者无法从仓库发现约束。
- 将完整检查套件固定到每次提交：增加局部检查点成本，保留按改动风险选择验证的方式。
- 将实现与验证细节继续堆入 README：会掩盖使用者最先需要的安装和使用信息。
- 新增并列的 agent.md：与已有 AGENTS.md 形成两个协作入口，因此复用现有文件。

## Consequences

流程规则随仓库版本管理；后续非平凡变更需要维护拥有决定的记录。当前未引入自动化文档检查或 Git hook（钩子），文本规则仍依赖协作者执行，不构成自动门禁。

移动文档内容时同步修复链接和事实归属；隐私、安装限制及统计口径继续留在产品入口，不能随实现细节一起隐藏。
