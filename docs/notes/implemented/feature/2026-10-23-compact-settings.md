# Agent Note: Compact native settings

Status: implemented

## Problem

设置窗口的页面分段与显示模式分段层级相近，更新页的品牌区占据较多空间，两页的边距和字号缺少统一节奏。全量字体下拉列表也增加了查找成本。用户确认紧凑的原生工具栏、统一分组和克制字号层级。

## Decision

由 `NSTabViewController` 管理页面选择，窗口采用 `unifiedCompact` 工具栏，原生按钮横排图标与文字；SwiftUI 页面共用分组、行和字体层级。设置窗口保持固定尺寸，内容可纵向滚动，使长说明仍可访问。尺寸与视觉契约由[界面设计说明](../../../interface-design.md#菜单栏设置)维护。

以系统字体面板替代应用枚举字体列表，继续保存既有字体名称，菜单提供返回系统默认的入口。面板只负责字族和字形，字号继续由原有范围控制。字体操作目标由设置控制器持有；离开菜单栏页或关闭设置时清除目标并关闭面板，迟到回调不更新偏好。此决定部分取代[菜单栏偏好](2026-10-22-menu-bar-preferences.md)的字体列表实现，其存储与渲染约束保持有效。

更新页缩小品牌区，突出状态与检查操作；仍仅转发到应用级更新控制器，不改变[更新生命周期](../architecture/2026-10-23-sparkle-updates.md)。有历史检查时间但本次启动尚未检查时，不将其描述成从未检查或已是最新。

## Alternatives considered

- 原生 `.preference` 两行工具栏：实测顶部约 80 pt，红绿灯上方留白不符合紧凑目标；改为单行紧凑样式，保留系统红绿灯布局。单独切换工具栏样式会隐藏页面文字，因此用原生按钮保留图标和标题。

- 保留内容区分段导航：容易与显示模式混淆，原生偏好工具栏能表达页面层级并提供系统键盘及可访问性行为。
- 增加侧栏：只有两个页面，不值得额外占据横向空间。
- 自建可搜索字体列表：需要继续维护字体枚举、过滤和选择状态；系统面板已提供字族、字形及集合选择。
- 通过缩小所有文字或禁止滚动压缩窗口：会损害阅读和长错误说明的可达性；改为统一文字层级并减少间距。

## Consequences

系统决定工具栏的具体高度、字体面板外观和控件尺寸，不保证与概念图逐像素一致。字体面板与设置页共同完成字体和字号选择，不支持颜色或装饰设置。

真实预览使用与应用相同的窗口入口，包含浅深色工具栏、显示模式、字体回退和更新状态。菜单栏检查通过原生字体面板消息验证即时保存、字号边界、切页关闭和窗口释放；非法字号及无编辑目标的回调作为负向输入。其他 macOS 版本和 VoiceOver 的完整人工操作仍需另行验证。
