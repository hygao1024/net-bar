# Agent Note: Compact panel and address truncation

Status: implemented

## Problem

菜单栏面板横向占位偏大，长 IPv6 换行还会挤占进程列表的纵向空间。用户希望快速浏览紧凑面板，完整地址不应决定面板尺寸。

## Decision

收窄固定面板宽度和速率列，保留现有字体尺寸，让进程名称使用剩余宽度。进程速率按当前单位四舍五入保留一位小数，读屏使用相同格式，排序与活跃状态继续使用原始数值。复用现有格式化入口的一位小数选项，默认精度仍服务菜单栏提示，不改变菜单栏的设置。本机与公网地址使用原生单行尾部省略，悬停提示、点击复制和辅助功能仍使用完整原始地址；不按字符数提前裁剪数据。单个本机 IPv6 与 IPv4 使用相同的行高。

进程列表隐藏原生滚动指示条，以减少右侧视觉占位；继续使用 ScrollView，保留滚轮与触控板滚动。使用 `.never`，避免系统“始终显示滚动条”设置覆盖 `.hidden`；长列表预览已暴露后者仍显示滑块的问题。

底部只呈现完整进入可视区域的行。使用行在滚动容器中的实际位置判断显示，不通过缩小字体、改变行高或截断数据填满余量；保留原生连续滚动，部分行完整进入后恢复显示。

此决定取代[网络信息](2026-10-22-network-overview.md)中的长地址换行方案；地址查询、缓存、取消及多接口局部滚动规则继续有效。当前尺寸由[界面设计说明](../../../interface-design.md#视觉标记)维护。

## Alternatives considered

- 为完整地址保留较宽面板或多行显示：增加整体占位，违背紧凑浏览的需求。
- 缩小字体：损害地址与速率的可读性，使用地址省略与减少速率小数位即可控制占位。
- 保留列表两位小数及较宽速率列：不符合用户在保留一位小数的同时收窄面板的需求。

## Consequences

列表随剩余高度伸缩的布局由[正方形列表卡片](2026-10-31-square-traffic-card.md)取代；底部按实际位置隐藏半行的规则继续保留，仅在连续滚动未对齐整行时可能留下不足一行的空白。滚动和排序更新时按实时几何位置重新判断。隐藏滚动条后不再显示滚动位置，也不能拖动滑块；长列表仍可滚动访问。小于 0.05 KB/s 的非零速率会显示为零，但仍计为正在传输，原始速率排序也可能使相同显示值的行顺序不同。长地址和进程名称会更早截断，完整内容通过已有悬停提示访问，地址复制不受影响。真实视图离屏预览覆盖浅深色、长公网 IPv6、多接口和单个本机 IPv6；离屏图片不能替代实际悬停、键盘及读屏交互检查。
