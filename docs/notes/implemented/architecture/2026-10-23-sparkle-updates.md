# Agent Note: Signed Sparkle updates

Status: implemented

## Problem

GitHub 上发布标签和安装包不会使已安装的应用自动发现更新。需求包括手动检查、定期检查、后台下载和替换安装，同时继续使用临时签名，仅发布 Apple Silicon 版本。

## Decision

采用锁定版本的 Sparkle 2，替代自建版本比较、下载器、验签、安装助手和恢复流程。`UpdateController` 由应用持有，只投影 Sparkle 的状态并转发设置与用户操作；设置窗口不拥有更新会话，也不重复保存 Sparkle 偏好。核心采样模块继续不依赖更新框架。测试只替换 Sparkle 的用户交互驱动，下载、验证、替换和重启均运行真实组件。

临时应用签名不承担发布者身份验证，客户端固定 Ed25519 公钥，并要求解压前验证安装包与验证更新清单。关闭清单签名失败的超时降级，避免无 Apple Developer ID（开发者身份）凭据时放宽信任。私钥独立存放于专属钥匙串账户和 GitHub Secret；不支持在普通更新中替换公钥。

GitHub Release 同时承载签名清单和安装包，草稿阶段上传完整附件后再公开，客户端从最新正式 Release 取清单，再从固定版本 URL 下载包。`Info.plist` 拥有版本和构建号；发布校验阻止构建号倒退、标签不一致、错误签名和公钥改变。仅构建 arm64，使用 Sparkle 生成的硬件条件排除 Intel 客户端。

设置保留独立窗口和实时菜单栏预览，增加软件更新页。应用标记、版本与更新状态形成阅读顺序；下载和安装使用 Sparkle 原生窗口，避免维护第二套有权限和取消语义的交互。此决定扩展[菜单栏设置](../feature/2026-10-22-menu-bar-preferences.md)的窗口职责，采样与字体设置约束不变。

## Alternatives considered

- 只查询 GitHub API 并跳转下载：不能满足后台下载与自动替换安装。
- 自建安装助手：必须自行维护进程退出、目录权限、签名和失败恢复，维护责任明显高于接入成熟框架。
- 依赖 Apple Developer ID 验证：用户没有开发者证书；Ed25519 独立于 Apple 证书满足当前更新信任需求。
- 同时生成 Intel 和 Apple Silicon 通用包：当前只需 arm64，不扩大交付与验证范围。

## Consequences

项目新增一个二进制依赖与相应工具许可；发布需要保护和备份更新密钥。丢失私钥无法借助临时签名轮换公钥，恢复需要用户手动安装。未集成更新功能的旧版本也需要先手动升级一次。Sparkle 不消除首次安装的系统安全检查限制。

实际运行已覆盖隔离临时签名应用的手动升级重启、后台下载和退出安装，以及篡改清单和包的拒绝。正式 GitHub 下载、安装授权与登录项兼容仍需对应环境验证；发布命令、密钥迁移和恢复操作由[发布文档](../../../releases.md)拥有。
