# Agent Note: Arrowless menu panel

Status: implemented

## Problem

用户希望去掉菜单栏面板顶部的指向箭头。NSPopover 的公开接口不支持隐藏箭头，修改内部视图或使用私有键会依赖系统实现细节。

## Decision

以无边框 MenuPanel（NSPanel 子类）替换 NSPopover。子类只负责窗口配置、键盘取消和定位计算；AppDelegate 继续拥有内容创建、显示、关闭、事件监听和采样生命周期。窗口与内容按需创建，所有关闭路径汇聚到窗口关闭回调，先撤销点击监听，再停止采样与地址查询、释放窗口和控制器。独立的排序偏好继续跨面板重建保留。

窗口可成为键盘目标，Esc 通过 cancelOperation 关闭。打开期间安装本地和全局鼠标点击监听，点击窗口外部即关闭；监听弱引用当次窗口并核对窗口身份，防止旧回调关闭新面板；本地监听排除菜单栏按钮所在窗口，让按钮自己的开关动作完成关闭，避免按下时关闭、松开时又重开。打开设置、应用失活、休眠、用户会话离开、工作空间或屏幕变化都关闭面板，避免隐藏窗口仍保留采样。

位置由真实菜单栏按钮转换到屏幕坐标后计算，在所在屏幕可见区域内约束边缘；顶部使用较小间距以强化与菜单栏入口的关联，左右和底部仍留出安全边距；菜单栏宽度更新时重新定位。屏幕或工作空间切换后由下次点击重新定位，不保留失效锚点。窗口使用透明背景和系统阴影，内容拥有圆角与细描边；[原生材质](../feature/2026-10-31-panel-material.md)继续保留。

## Alternatives considered

- 保留 NSPopover：原生定位与关闭行为更省维护，但无法通过公开接口去除箭头。
- 调整私有属性或裁剪系统内部箭头视图：对系统版本敏感，也会让材质、轮廓和命中范围不一致。

## Consequences

应用承担原先由 NSPopover 管理的定位和关闭行为，必须同步维护事件监听的生命周期。无箭头后失去显式指向提示，以面板位于按钮下方保持来源关联。

菜单栏检查使用真实 AppKit 事件循环，避免只有异步调度时无法取得键盘焦点。定位负向检查临时移除屏幕边缘约束后，原生检查以定位越界错误拒绝，随后恢复生产实现。

现有内存检查迁移到真实 NSPanel 关闭路径，覆盖窗口和控制器释放以及排序保留；真实菜单栏检查覆盖屏幕边缘定位、Esc、外部点击、设置切换、快速重开、模拟系统通知及真实采样取消。自动检查不会切换实际显示器或用户工作空间，不替代不同 macOS 版本、多显示器和全屏应用下的人工交互验证。
