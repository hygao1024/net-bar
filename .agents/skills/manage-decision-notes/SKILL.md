# 管理 Agent Notes

Agent Note 保存代码和测试难以表达的原因、取舍和后果。触发条件、活动 lifecycle（生命周期）、分类和文件格式由 `.agents/notes/README.md` 唯一拥有；本 skill 负责查重、取代、未来价值和归档判断。

## 查重与范围化审计

- 先通过代码、文档、测试和当前状态解决可发现事实，再只搜索三个活动 lifecycle 中相同术语、接口、机制和决策范围；已有记录仍拥有决定时更新它，不创建平行所有者。
- 每个新 Note 都审计同一决定、机制或落选方案范围内的活动记录；不因新增一条记录默认审计整个仓库。
- 新决定改变旧决定时，新建记录；部分取代或仍有独立价值的理由保留旧记录并双向链接。
- 完全被取代的 implemented 记录只有在当前所有者吸收全部独有理由、替代方案、后果、必要验证和覆盖缺口，并修复入站链接后才能删除；不能只依赖 Git 历史保存理由。
- 代码、协议或配置是当前行为事实；Agent Note 是决策理由事实。发现不一致时判断实现漂移还是记录过时，不把任一方当作不可修改的真理。

## 生命周期和未来价值

- implemented 记录只在理由、替代方案、负面保证或重新评估条件仍可能指导未来选择时保持活动；年龄、字数和引用次数只能帮助发现候选。
- proposed 不再推进时，仅在落选方案仍能防止现实误判时转为 rejected，否则删除；rejected 不再防止有诱惑力的错误时修复入站链接后删除。
- 全仓生命周期审计只在用户明确要求、活动语料明显妨碍发现，或变更触发大范围取代时进行，不按配额归档。

## 更新与归档

- 按 `.agents/notes/README.md` 更新当前事实；范围、责任边界、恢复或重新评估条件只有在适用且非显而易见时记录，不用模板字段填充篇幅。
- 归档时从 `implemented/<class>` 原样移动到 `archived/<class>`，正文不变，只增加 `Archived: YYYY-MM-DD`；活动入站链接转向当前权威、在确需引用历史时改指归档，或删除，不修复归档的出站链接。
- 归档必须通过目标仓库已有的冻结守卫；没有真实归档或原生守卫时保持 active（活动），不临时自创 manifest（清单）协议。
- 修改后运行目标仓库已有的 Agent Note 与文档检查，并报告无法确定的取代关系、合并完整性、未来价值或入站引用。
