# Prose And Docs

这是跨技术栈的文档评审 skill。它负责语义完整性和事实归属，不替代目标仓库自己的文档层级、双语、预算、生成或发布策略。

## 范围和权限

- 从用户请求或已确认的真实 diff 得到明确 scope（范围），不把局部任务静默扩大为全仓审计；无法确定且不同范围会改变结论时先请求确认。
- Review、审计和诊断只报告问题；只有明确的编写、修复或整理请求才修改文件。
- 冻结归档不参与日常编辑。snapshot（快照）、fixture（测试前置数据）、生成目录和目录清单是 derivative artifact（派生产物）；先修改事实来源或生成器，再按仓库入口重建。
- 目标仓库声明的双语配对、文档预算、站点导航或生成规则只在实际存在时适用，不提升为通用要求。

## 事实和结构

- 先确定事实所有者：代码表达行为，测试表达可观察结果，README 或 reference（参考文档）表达当前消费者契约，Agent Note 表达长期原因和取舍。一份解释只有一个归属；调用点安全使用所需的行为、失败、时序和所有权事实可以局部重复，理由链接到所有者。
- 按用途判断文档形式。Tutorial（教程）以有序操作到可观察结果为主；reference 支持范围明确的查询；Agent Note 记录决定；混合内容只有在拆分能减少读者负担时才拆分。
- 文档只完整展开自己的主题，子主题保留必要局部契约、职责和链接；避免手写易漂移的文件、命令、状态或测试清单。
- 移动或重命名文档、标题和锚点前搜索入站引用；移动必须与来源删除、目标创建和引用修复在同一变更中完成。

## 按载体补足契约

- Public API（公共接口）和 JSDoc（JavaScript 文档注释）说明调用方可见的返回差异、失败、side effect（副作用）、所有权、时序、取消和持久性；代码或类型已经清楚表达的事实不再复述。
- README、reference 和 Tutorial 面向消费者说明适用范围、前置条件、配置、语义、失败、限制、扩展点和可观察验证；只保留该文档拥有的内容，跨主题理由链接到所有者。
- Module comment（模块注释）、测试注释和 diagnostic（诊断）只补足非局部职责、非显而易见的 invariant（不变量）、fixture 选择或间接观察原因；诊断应指出失败主体、违反的规则，以及不明显时的修正方向。

## 保留完整命题

- 保留适用的主体、条件、时序、强制程度、否定保证、例外、所有权、副作用、失败和后果。缩短字数本身不是改进。
- 其他注释只说明代码难以表达的调用方契约、生命周期、并发顺序、安全约束或非显而易见原因；删除代码复述和控制流旁白。
- 删除测试步骤、审查对话、实现过程和临时状态；不删除仍会防止误用的原因、覆盖缺口或恢复条件。
- 配置、默认值、错误、公开接口、用户可见文本或开发命令变化时，同步更新拥有该事实的文档和示例。
- 用户、模型或协议可见文字视为行为。非平凡变化通过真实可运行组合验证；目标仓库已有可重复的 keyless snapshot（无凭据快照）能力时更新或扩展它，否则运行真实入口 smoke test 并说明限制和残余风险。

## 验证

运行 scope 对应的仓库文档检查、可见行为检查和 `git diff --check`。自动检查只证明链接、格式或生成一致性等实际覆盖内容，语义准确性仍由 Review 对照事实所有者判断。
