# Defensive Patterns

这是跨技术栈的实现与评审 skill，用于检查生命周期和信任边界中容易遗漏的缺陷类别。它是判断指导，不是完整 checklist（检查清单）；只展开当前改动真实涉及的分支，不替代目标仓库自己的测试和安全策略。

## 判断方法

- 区分 typed same-process（同进程类型化）输入与 parser（解析器）、配置、队列、模型或工具 JSON、持久化、worker（工作线程）、进程和 wire（线协议）输入；在真正拥有操作的边界验证，不能用 schema（模式）、UI 或 wrapper（包装层）代替执行层保护。
- 同一结果存在 throw（抛出）、返回值、事件或状态等多种内部表示时，在 public API（公共接口）的事实所有者处归一化；调用方不应猜测结果来自哪一种内部路径，并通过真实消费者覆盖每种来源。
- 为异步状态标出所有者和完成区间。检查初始化期间的重入、取消发生在 `await` 期间、重复终止、迟到回调和“没有状态可等待”的分支；不要把共享的 idle（空闲）状态误当作单次操作结果。
- 独立报告可同时成立的结果，例如 timeout（超时）、signal（信号）和 exit code（退出码）；一个结果不能遮蔽另一个。子进程或 worker 还要处理启动失败、输出上限、父级取消和孤儿回收。
- teardown（清理）必须达到 quiescence（静止状态），而不只是发出终止请求；先关闭通知入口，再终止并等待所属资源退出。用户回调的异常应在 dispatcher（分发器）中隔离，不能中断核心生命周期或后续回调。
- 涉及权限、凭据、临时文件或路径删除时，检查允许、拒绝、替代入口和平台语义；不把 ambient environment（环境变量全集）或可预测路径交给不受信任输出。可能是 symlink（符号链接）或 Windows junction（目录联接）的路径先用目标运行时中不跟随链接的 metadata API（元数据接口）确认，再用只删除链接本身的 API 移除；Node.js 对应 `lstatSync().isSymbolicLink()` 后 `unlinkSync()`。递归删除只作用于已经确认的真实目录。

## 验证与交付

新增或修改 guard（守卫）时，用真实违规的 negative control（负向控制）证明检测路径有效，并观察外部状态、结果或资源收敛。无法运行真实入口或目标平台检查时，报告具体限制和残余风险；不要用 mock-only（仅模拟）结果替代。
